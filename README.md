# LLM 多 Agent 协作中的「高价值信息被忽视」

**一份验尸报告：7 条失效机制、7 个闸门模板、21 处审核修复——全部来自单一项目的真实事故，零跨项目验证。**

> **读它的人**：正在用多个 LLM agent 并行做同一件事、共享一个文件系统、且会执行**不可逆动作**（提交 / 发布 / 部署 / 删数据）的人。
> **它不是什么**：不是框架、不是 checklist 产品、不是"最佳实践"。它的核心结论是**"修了也不会赢"**（见正文 §1.5），以及**"这些失效不能靠加强意识修复，只能靠闸门"**。

## 三个最反直觉的结论

1. **"诚实写下风险"是无效机制。** 本项目有四处独立记录，风险都写对了，**四次都没拦住**。诚实装置需要**外部回签**才有否决权（§2 M7 + §3.1 的回签机制）。
2. **"多个点全部吻合"常常是零信息。** 若"吻合"是算术必然（定义式），这列表什么也没证明。判据是一句话："若我的假设为假，这里面有几个点会不吻合？" 答 0 ⇒ 作废（§2 M2 / §3.2）。
3. **修这些护栏不会让你赢。** 量化反事实：全部叠加后 **4.78 vs 对手 5.57**（满分 7）。护栏的作用是**不要把资源浪费在自伤上**，不是胜利保证（§1.5）。

## 诚实声明（请连同正文一起引用）

- **零跨项目验证**：全部结论来自单一项目。有"项目内重复"（同一失效在 5 个不同任务、5 个不同 agent 上各命中一次），但**没有跨项目对照**。
- **数字未经第三方核查**：文中数字均为当班记录；审核方明确声明"未核实任何史实数字"。
- **这份文档本身被审过一轮**：三位独立审稿人提出 21 处问题（含 2 处致命：§3.1 是"诚实装置"却无闭环、§3.2 能被老实回答绕过），已逐条修复，见 [AUDIT_RESPONSE.md](AUDIT_RESPONSE.md)。
- **它的价值不在"正确"，在"可反驳"**：每条机制都给了可观测的失效判据（§4），你可以用它来判我错。
